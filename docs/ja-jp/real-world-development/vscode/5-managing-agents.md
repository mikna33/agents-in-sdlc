GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行などを自律的に行います。VS Code の Copilot Chat では、自分のマシンでリアルタイムに実行される作業について、ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、変更ごとに採用または却下したり、エディターを離れずに追加のプロンプトで会話を方向付け、作業を改善・拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。デフォルトのテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいとのことです。最初から新しい会話を始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順（調査するファイル、実行するコマンド、提案する編集）が表示されます。ファイル編集ごとに差分がチャットにインラインで表示され、**Keep** / **Undo** を選択できます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を元に戻して、エージェントにやり直してもらうには **Undo** を選択します。
4. チャット上部の **Files changed** インジケーターを開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出しで許可が必要な場合（たとえば、ターミナル コマンドの実行）、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。変更内容を要約した最終メッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは前の作業のコンテキスト（変更したコンポーネント、スタイルのアプローチ、設定したローカル ストレージのパターンなど）を保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはすでに加えた変更を調べ、そこから作業を続けてライト モードの追加を提案します。
3. ハイ コントラストのときと同様に、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントの作業の方向が希望と異なる場合（たとえば、好みでない方法でトグル UI をリファクタリングしようとしている場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確にするための追加メッセージを送信できます。

> [!TIP]
> 進行中のセッションを方向付ける方が、最初からやり直すよりも速く済みます。追加プロンプトで調整（「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使ってください」）、軌道修正（「3 つ目のトグルは追加せず、ライト モードを既存の設定パネルに組み込んでください」）、範囲の拡張（「両方のトグルにキーボード ショートカットも追加してください」）ができます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターン（ARIA 属性、キーボード ナビゲーション、セマンティック HTML、ローカル ストレージでの保持）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視して方向付けました。ファイル編集を確認して採用または却下し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を採用および却下する方法。
- 追加プロンプトでセッションの進行中に方向付ける方法。
